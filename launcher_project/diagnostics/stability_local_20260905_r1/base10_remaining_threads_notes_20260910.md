# P1剩余线程初查笔记（2026-09-10）

参照R16b工作树。185引用/76方法清单仍待完整人工分类，以下是局部证据，不关闭整个方法/功能问题。

- ee.run的Wi-Fi分支（selector0）和ie.run默认蓝牙分支都等待300ms后通过既有ADB/设置启动路径打开用户选择的设置界面。这是用户操作，不是可替换状态查询。普通面板关闭可能正是该操作流程的一部分，不能据此取消启动；应继续核对点击生产者、永久销毁和重复动作策略。没有执行这些ADB命令。
- ea.run的`:pswitch_1c`包含`initCmdTools`连接初始化：循环内只检查静态NavBarService.O0非空，未在所见循环位置比较它与捕获的Service；InterruptedException后继续计数重试。连接成功后还执行既有全局设置初始化并投递m9、调用Service后续初始化，因此不能按纯读取放入丢弃队列。下一步核对selector、构造器生产者、完整失败出口及Service替换/销毁时序，再决定守卫和清理。
- 该ea分支所见循环sleep为`min(attempt*1000,5000)`，不是玻璃背景的300ms。完整尝试上限还需对照run入口寄存器及所有跳转；没有把sleep上限误称为整个ADB调用超时。
- h2全部12处构造调用已在R15收尾中分类，只有MainActivity selector1为模糊生成。剩余900/350ms等待属于应用启动动作；相关车控/应用操作分支保持原样，不能并入最新状态读取池。
